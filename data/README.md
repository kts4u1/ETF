# data/

## delisted.csv · delisted.meta.json

상장폐지된 ETF 목록과, 그 목록을 만든 KRX 기준일. `npm run sync`가 시세를 받아 `npm run backtest`의 유니버스에 포함해
**생존편향**(현재 상장 중인 ETF만 평가해서 부진했던 ETF가 빠지는 문제)을 줄입니다. 파일이 없으면 이 단계는 건너뜁니다.

이 두 파일은 **저장소에 커밋합니다.** KRX 종목 목록과 네이버 시세라는 공개 사실에서 만든 것이고, 커밋된 백테스트 결과(`docs/BACKTEST.md`,
`public/data/backtest.json`)가 이 파일에 의존하기 때문입니다.

### 만드는 방법 (권장): KRX 과거 시점 '전종목 시세' 파일

KRX에는 "지금까지 상장폐지된 ETF" 목록을 바로 주는 화면이 없습니다(로그인 필요·자동 수집 불가). 대신 **과거 날짜의 ETF 전종목 시세**를 받으면
그 날 상장돼 있던 ETF 목록을 알 수 있으므로, 현재 목록과 비교해 사라진 종목을 찾습니다.

1. https://data.krx.co.kr 에서 ETF **전종목 시세** 화면을 엽니다(메뉴 이름·위치는 KRX가 바꿀 수 있습니다).
2. **조회 일자를 과거 날짜로 바꾼 뒤 반드시 '조회'를 다시 누르고** CSV로 내려받습니다. 날짜만 바꾸고 조회를 누르지 않으면 오늘 데이터가 그대로 내려옵니다.
3. 받은 파일로 실행합니다. 파일에는 날짜가 없어 도구가 종가를 시세 캐시와 대조해 **그 파일의 날짜**를 추정합니다.

   ```bash
   npm run sync                                   # 먼저 현재 목록·시세 캐시가 있어야 합니다
   npm run derive-delisted -- 파일1.csv 파일2.csv
   npm run backtest                               # 상장폐지 ETF를 포함해 다시 계산
   ```

   - 오래된 파일은 배당 보정(시세는 수정주가) 때문에 종가 일치율이 낮아져 날짜 추정이 실패할 수 있습니다. 그때는 **파일 1개씩** `--date YYYYMMDD`(또는 `--date=YYYYMMDD`)로 날짜를 지정합니다.
     지정한 날짜도 종가가 10% 이상 맞아야 통과하므로, 날짜만 우겨서 통과시킬 수는 없습니다(시세 캐시에서 비교할 수 있는 종목이 20개 미만이면 종가 검증은 생략되지만, 아래 '오늘 데이터 거부'와 행 수 검사는 그대로 적용됩니다).
     파일을 여러 개 주면서 `--date`를 쓰거나, 값이 없거나 두 번 쓰거나, 달력에 없는 날짜(`20260230`)를 주거나, 모르는 옵션을 주면 실행하지 않고 이유를 알려줍니다.
   - 종료 코드: 0 정상 · 1 인자 오류 · 2 거부된 파일이 있음(통과한 파일의 결과는 저장됨) · 3 시세 수집 실패가 있어 저장하지 않음.

도구가 하는 일과 확인하는 것 (아래의 **데이터 기준일**은 `public/data/snapshot.json`의 시세 기준일, **파일 날짜**는 KRX 파일의 날짜입니다):
- 파일의 종목 중 **현재 상장 목록에 없는 것**을 후보로 삼고, 네이버에서 시세를 받아 **시세 마지막 행이 데이터 기준일 7일 이내면 '아직 거래 중'**(코드 변경 등), 시세가 60거래일 미만이면 '시세 부족'으로 제외합니다. 나머지가 상장폐지입니다.
  저장되는 `상장폐지일`은 시세의 마지막 행 날짜입니다(거래량 0으로 직전 종가를 반복하는 상장폐지일 행이라, 실제 마지막 거래일은 그 전 거래일입니다).
- **전종목 파일이 아니면 거부합니다**: 읽은 종목이 100개 미만(헤더만 있는 파일 등)이면 날짜를 지정해도 거부합니다(전종목 시세는 2020년 말에도 390개를 넘었습니다).
- **오늘 데이터는 거부합니다**: 파일 날짜가 데이터 기준일 7일 이내이거나, 파일의 종목이 현재 목록과 양쪽 모두 99.5% 이상 겹치면(신규 상장 몇 개가 섞여도) "과거 데이터가 아니라 현재 데이터"라고 알리고 건너뜁니다.
- `--date`로 지정한 날짜가 종가로 추정한 날짜와 다르면 거부합니다.
- 시세를 받지 못한 후보가 하나라도 있으면(네트워크·요청 제한) 오류로 보고하고 **아무것도 저장하지 않습니다**. 같은 날 다시 실행하면 받은 시세는 캐시에서 읽고 나머지만 받습니다.
- 결과는 `delisted.csv`와 `delisted.meta.json`(사용한 파일 날짜)에 기록됩니다. 같은 종목이 다시 도출되면 **새 값으로 갱신**합니다(시세의 마지막 행 날짜, 그리고 한 번에 준 파일 중 가장 최근 파일 날짜의 종목명). 실행을 나눠 이른 날짜 파일을 나중에 주면 그 파일의 종목명으로 덮어쓰므로 여러 파일은 한 번에 주는 것이 좋습니다. 직접 고친 값은 유지되지 않으니, 손으로 고칠 일이 있으면 도출 후에 고치세요.
  변동 없이 다시 실행하면 "신규 0, 갱신 0"으로 나오고 파일이 그대로입니다.

**범위의 한계**: 파일 날짜 시점에 상장돼 있다가 이후 사라진 ETF만 잡힙니다. 가장 이른 파일 날짜 이전에 폐지된 ETF, 그리고 파일 날짜들 사이에 새로 상장했다가 다음 파일 날짜(없으면 현재) 이전에 폐지된 ETF는 빠집니다.
파일 날짜가 촘촘하고 이를수록 범위가 넓어집니다(6개월 간격 권장). 현재 파일 날짜는 `delisted.meta.json`에 있습니다.

### 직접 만들기

`delisted.csv`를 직접 작성해도 됩니다(헤더 있는 CSV 또는 TSV, UTF-8과 EUC-KR 모두 읽음). 이 경우 `delisted.meta.json`이 없으면 범위를 알 수 없다고 표시됩니다.

| 열 | 필수 | 설명 |
|---|---|---|
| 종목코드 (또는 단축코드, code) | ✅ | 6자리. `A069500`처럼 `A`가 붙어도 됩니다 |
| 종목명 (또는 name) | ✅ | 자산군·테마 분류에 사용 |
| 상장폐지일 (또는 delistedOn) | | `YYYYMMDD`, `YYYY-MM-DD`, `YYYY/MM/DD` |

형식 예시는 `delisted.example.csv`.

### 계산 방식

- 시세는 네이버 금융에서 받습니다. 받지 못한 종목은 사유와 함께 건너뜁니다.
- 보유 도중 시세가 끝나는 ETF는 **마지막 가격에 청산된 것으로** 계산합니다(평가에서 조용히 빠지지 않습니다).
- 이름만으로 분류하므로 일부가 틀릴 수 있습니다(예: 외국 채권 지수 이름). 현재 데이터에서는 결과에 영향이 없음을 확인했습니다(설계 문서 §9).
- 만기가 있는 채권형 ETF(예: `26-06 회사채`)는 부실이 아니라 만기 청산이라 대체로 손실 없이 끝납니다. 즉 폐지 목록 안에는 '실패'와 '정상 만기'가 섞여 있습니다.
